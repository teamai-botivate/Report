PROJECT: AI-NATIVE BUSINESS INTELLIGENCE & DASHBOARD BUILDER

You are the lead architect and senior full-stack engineer.

Build a production-quality MVP of an AI-Native Business Intelligence platform that works conceptually like Power BI/Tableau, but with a major difference:

THE USER CAN TALK TO THE DASHBOARD.

The user should be able to ask questions, create reports, create charts, modify dashboards, calculate metrics, compare business data, move/resize/style components, and export results using natural language.

At the same time, the application MUST have a powerful manual dashboard editor so everything can also be controlled manually.

==================================================
1. CORE PRODUCT VISION
==================================================

The application is a business intelligence system connected to ONE large structured Neon PostgreSQL database.

The database contains multiple interconnected business systems/modules:

- HR
- Sales
- Purchase
- Inventory
- Production
- Order-to-Delivery
- Tasks
- Finance
- Customers
- Suppliers
- Products
- Departments
- Employees
- Branches
- Warehouses
- Calendar/Date dimensions
- Other supporting master data

There must be NO requirement for the user to manually upload CSV files or manually enter business data for the demo.

The system itself must create and seed a large realistic dummy business database in Neon.

The database must be properly relational and structured.

Use:

- Primary keys
- Foreign keys
- Relationships
- Indexes
- Constraints
- Proper data types
- Date dimensions
- Master tables
- Transaction tables
- Status fields
- Realistic business relationships

The goal is to simulate a real company database.

==================================================
2. VERY IMPORTANT: SINGLE SOURCE OF TRUTH
==================================================

Neon PostgreSQL is the source of truth.

The AI must NEVER invent business numbers.

Every business number shown to the user must come from:

Neon database
+
validated SQL/query results
+
deterministic calculations

The LLM can decide:

- what data is needed
- which tables are relevant

- which visualization should be used

==================================================
9. SQL SAFETY
==================================================

This is critical.

The AI must NEVER receive unrestricted database write access.

Create a READ-ONLY database user/connection for AI-generated analytical queries.

Only SELECT statements should be allowed.

Block:

INSERT
UPDATE
DELETE
DROP
ALTER
TRUNCATE
CREATE
GRANT
REVOKE

Implement SQL validation before execution.

Use:

- SQL parser/AST validation
- statement allowlist
- query timeout
- row limits
- result size limits
- protected tables if necessary
- audit logs

Every AI-generated query should go through:

Generate
-> Parse
-> Validate
-> Safety Check
-> Execute
-> Validate Result
